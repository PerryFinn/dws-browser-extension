# 智能书签搜索

## 概述

在 Options 页面新增「智能书签」路由，用户输入自然语言描述，调用大模型对浏览器原生书签进行语义搜索，返回最相关的书签结果。

## 核心流程

1. 用户在搜索框中输入自然语言查询
2. 扩展调用 `chrome.bookmarks.getTree()` 获取完整书签树
3. 将书签列表（标题 + URL + 目录路径）与用户查询组装为 prompt，发送给大模型
4. 大模型返回匹配结果（排序 + 匹配理由）
5. 展示结果列表，支持一键打开或复制链接

## 模块划分

### Options 路由

- 路径：`/bookmarks`
- 位置：`src/options/routes/bookmarks/index.tsx`

### 模型配置

- 独立于现有「通用提取模型配置」，在该页面内提供专用配置
- 字段：API 地址、Model ID、API Key
- 存储：`chrome.storage.local`（key: `bookmarkSearchModelConfig`）
- 支持「测试连接」功能

### 书签服务

- 封装 `chrome.bookmarks.getTree()`
- 递归扁平化书签树为 `{title, url, path}[]`
- 过滤无 URL 的文件夹节点

### 搜索服务

- 组装 prompt（书签列表 + 用户查询）
- 调用大模型 API（OpenAI 兼容，POST /chat/completions）
- 解析 JSON 响应，映射回书签对象

## UI 设计

### 页面布局

```
┌─────────────────────────────────────────────┐
│  搜索框（placeholder: "描述你要找的书签..."）    │
│  [搜索按钮]                                    │
├─────────────────────────────────────────────┤
│  搜索结果列表（最多 10 条）                     │
│  - 书签标题（可点击打开）                       │
│  - URL + 目录路径                              │
│  - 匹配理由                                    │
├─────────────────────────────────────────────┤
│  ⚙️ 模型配置（可折叠，默认折叠）                │
│  API 地址 / Model ID / API Key / 测试连接 / 保存│
└─────────────────────────────────────────────┘
```

### 交互细节

- 回车或点击按钮触发搜索
- 搜索中显示 loading 状态
- 结果按相关度排序，最多 10 条
- 每条结果：点击标题打开新标签页、复制 URL 按钮
- 模型配置区默认折叠；未配置时自动展开引导

## Prompt 设计

```text
你是一个书签搜索助手。用户有以下书签列表，请根据用户查询找出最相关的书签。

## 书签列表
1. [标题] | [URL] | 目录: [路径]
2. ...

## 用户查询
{用户输入}

## 要求
- 返回最多 10 条最相关的结果
- 按相关度从高到低排序
- 以 JSON 数组格式返回: [{"index": 1, "reason": "匹配理由"}]
- 如果没有相关结果，返回空数组 []
```

## 错误处理

- 模型未配置 → 展开配置区并提示用户填写
- API 调用失败 → 显示错误信息，允许重试
- 书签为空 → 提示"未找到浏览器书签"
- 模型返回格式异常 → 提示"解析结果失败，请重试"

## 技术决策

- **方案选择**：直接语义匹配（方案 A），将全量书签列表交给大模型做语义理解，实现简单且效果好
- **适用场景**：书签量 < 2000 条（token 消耗可控）
- **模型协议**：OpenAI Chat Completions 兼容格式
- **存储**：使用 `chrome.storage.local`，无需后端服务

## 权限

- 需要 `bookmarks` 权限（读取浏览器书签）
- 现有 manifest 中如未声明需新增
