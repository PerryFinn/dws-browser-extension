# 智能书签搜索

## 概述

在 Options 页面新增「智能书签」路由，用户输入自然语言描述，调用大模型对浏览器原生书签进行语义搜索，返回最相关的书签结果。同时在 Popup 中提供快捷跳转入口。

## 核心流程

1. 用户在搜索框中输入自然语言查询
2. 扩展调用 `chrome.bookmarks.getTree()` 获取完整书签树
3. 客户端预过滤：对书签做关键词初筛，缩小候选集（应对大书签量场景）
4. 将候选书签列表（标题 + URL + 目录路径）与用户查询组装为 prompt，发送给大模型
5. 大模型返回匹配结果（排序 + 匹配理由）
6. 展示结果列表，支持一键打开或复制链接

## 模块划分

### Options 路由

- 路径：`/bookmarks`
- 位置：`src/options/routes/bookmarks/index.tsx`
- 需在 `src/options/components/sidebar.tsx` 注册侧边栏导航菜单项

### Popup 快捷入口

- 在 Popup 中增加「智能书签」跳转按钮，点击后打开 Options `/bookmarks` 路由

### 模型配置

- 复用现有 `GenericModelConfig` 类型（`src/storages/generic-api-doc.ts`）和 `isGenericModelConfigComplete` 校验函数
- 使用独立的 storage key：`bookmarkSearchModelConfig`
- 复用现有连接测试逻辑
- 支持「测试连接」功能

### 书签服务

- 封装 `chrome.bookmarks.getTree()`
- 递归扁平化书签树为 `{title, url, path}[]`
- 过滤无 URL 的文件夹节点
- 提供客户端预过滤函数（基于用户查询的关键词拆分做初步匹配）

### 搜索服务

- 复用项目已有的 `@ai-sdk/openai-compatible` 基础设施调用大模型
- 组装 prompt（候选书签列表 + 用户查询）
- Token 预算控制：根据模型上下文窗口动态截断书签列表
- 解析 JSON 响应，映射回书签对象
- 支持 AbortController 取消前次未完成请求

## UI 设计

### 页面布局

```
┌─────────────────────────────────────────────┐
│  搜索框（placeholder: "描述你要找的书签..."）    │
│  [搜索按钮]                                    │
├─────────────────────────────────────────────┤
│  最近搜索（最多 5 条历史查询，可点击快速复用）    │
├─────────────────────────────────────────────┤
│  搜索结果列表（最多 10 条）                     │
│  - 书签标题（可点击打开）                       │
│  - URL + 目录路径                              │
│  - 匹配理由（默认折叠，hover 展开查看）          │
├─────────────────────────────────────────────┤
│  ⚙️ 模型配置（可折叠，默认折叠）                │
│  API 地址 / Model ID / API Key / 测试连接 / 保存│
│  首次使用引导卡片：说明为什么需要配置、如何获取   │
└─────────────────────────────────────────────┘
```

### 交互细节

- 回车或点击按钮触发搜索，输入有 300ms debounce（防止快速连续触发）
- 搜索中显示 loading 状态 + 进度文案（如"正在理解你的意图..."）
- 新搜索触发时通过 AbortController 取消前次未完成请求
- 结果按相关度排序，最多 10 条
- 每条结果：点击标题打开新标签页、复制 URL 按钮
- 匹配理由默认折叠，hover 或点击展开，减少视觉噪音
- 模型配置区默认折叠；未配置时自动展开，并显示引导卡片
- 搜索历史：缓存最近 5 条查询到 `chrome.storage.local`，展示在搜索框下方

## Prompt 设计

```text
你是一个书签搜索助手。用户有以下书签列表，请根据用户查询找出最相关的书签。

## 书签列表
1. [标题] | [URL] | 目录: [路径]
2. ...

## 用户查询
{用户输入}

## 要求
- 返回最多 10 条最相关的结果
- 按相关度从高到低排序
- 以 JSON 数组格式返回: [{"index": 1, "reason": "匹配理由"}]
- 如果没有相关结果，返回空数组 []
```

## Token 预算与大书签量策略

- 书签列表每条约 50-100 字符，2000 条约 50K-70K tokens
- **预过滤策略**：从用户查询中提取关键词，先在本地对书签做模糊匹配过滤，将候选集控制在 500 条以内再发送给模型
- **动态截断**：若预过滤后仍超出 token 预算（默认上限 30K tokens），按匹配度截断
- **超限提示**：书签量 > 2000 且关键词过滤后仍超限时，向用户提示"书签数量较多，结果可能不完整"

## 错误处理

- 模型未配置 → 展开配置区并显示引导卡片
- API 调用失败 → 显示错误信息，允许重试
- 书签为空 → 提示"未找到浏览器书签"，展示空状态插画
- 模型返回格式异常 → 提示"解析结果失败，请重试"
- 请求被取消（用户发起新搜索）→ 静默忽略，不展示错误

## 技术决策

- **方案选择**：直接语义匹配（方案 A），将书签列表交给大模型做语义理解，实现简单且效果好
- **预过滤**：客户端关键词初筛，控制发送给模型的 token 量
- **模型调用**：复用 `@ai-sdk/openai-compatible`，而非裸写 fetch
- **配置复用**：复用 `GenericModelConfig` 类型和校验逻辑，独立 storage key
- **存储**：使用 `chrome.storage.local`，无需后端服务

## 权限

- 需要 `bookmarks` 权限（读取浏览器书签）
- 在 `package.json` 的 `permissions` 数组中新增 `"bookmarks"`
- 现有 `<all_urls>` host_permissions 已满足 API 调用需求
